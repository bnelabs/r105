# r105 2.1.0

r105 2.1.0 replaces yesterday's sidecar ghost-text with a deterministic
completion cascade with zero weights. The 531MB model, the
`llama-server` dependency, and the provisioning question are all gone —
the composer got faster *and* lighter in the same change.

## Highlights

- **History-frequency ghosts.** Every `!` run is recorded with its
  workspace into a capped, persisted ring (`shell_history.json`).
  Suggestions score `10×runs + 25×same-dir runs + recency`, so the
  workhorse commands you repeat surface first.
- **Path top-hit.** When history has nothing, the last-token path
  fragment completes from the directory listing through the same
  scorer as the file menu.
- **Same ghost shell.** Debounce, dim render, Tab-accept chaining,
  Esc-dismiss-until-edit are unchanged; the tick is now synchronous
  (microseconds, no flights, no generations).
- **`/completion [status|clear]`** reports history counts or clears
  them. Stale sidecar config keys (`completion_endpoint`,
  `completion_model_path`, `completion_timeout_ms`) warn as unknown.

Terminal work is repetitive — frequency beats parameters. Spec 0016
under `docs/specs/` records the change and the findings behind it.
