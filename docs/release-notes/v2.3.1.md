# r105 2.3.1

r105 2.3.1 fixes the context budget: the footer bar, `/tokens`, and
auto-compaction now read the selected model's real context window
instead of a fixed default.

## Fixed

- **Model-accurate context window.** The footer showed a hardcoded
  262144-token window no matter which model was selected, so the
  percentage (and the 80% auto-compaction trigger) never matched the
  backend. The budget now resolves in priority order: an explicit
  `model_contexts` entry (exact key first, then the longest family key
  contained in the model id, with `*` as a catch-all), then the window
  a local llama.cpp server reports on `/props`, then per-model metadata
  from the provider's `/v1/models` (`context_length`, `max_model_len`,
  `meta.n_ctx_train`, …), then the global `context_tokens` setting.

- **Observed windows are live and incidental.** A silent startup probe
  fills the budget before the first `/models` — no overlay, no status
  change — and detected values are never written to session files.
  The `/models` overlay now labels each row with its reported window
  (`· ctx 128k`).

## Upgrade

Drop-in replacement for 2.3.0; config and sessions load unchanged. To
pin a window by hand, set `model_contexts` in
`~/.config/r105/config.json`, e.g. `{"qwen3": 131072, "*": 32768}`.
