# r105 1.4.0

r105 1.4.0 continues borrowing the best ideas from Warp — per-block
expansion, checkpoints with rewind, plugin hooks, session trees, and
input classification — reimplemented in r105's Rust style, with every
change recorded as a spec under `docs/specs/` (0001–0009).

## Highlights

- **Per-section expansion.** Collapsed tool sections render as one line
  with a stable `[n]` gutter id; `/expand [n|all|none]` opens or closes
  them. Failed tool calls always stay expanded so errors are never
  hidden behind a toggle.
- **Checkpoints and rewind.** `/clear` and `/compact` save a checkpoint
  first (kept to the last 10), and `/rewind [n]` restores an earlier one
  after backing up the current work, with a boundary notice marking the
  restore point. Destructive actions are undoable now.
- **Safer compaction.** Pair-aware context splits keep tool calls with
  their results, empty summaries are rejected instead of wiping context,
  and `/compact to retry` recovers after a failed compaction.
- **Plugin tool hooks.** Manifests can declare `before_tool` /
  `after_tool` hooks to deny a call with a visible reason or rewrite its
  arguments and result — policy gates and audit logging without forking
  r105. Hook failures fail the tool visibly, never silently.
- **Session tree.** Sessions record their parent, `/session fork <name>
  [turns]` snaps to an exchange boundary with tool-pair repair, and
  `/session tree` shows the fork hierarchy.
- **`#` classify prefix.** A `#` line is classified before anything
  runs: shell one-liners are prefilled after `!` for review, agent
  prompts are sent as-is, ambiguous input gets a status-line hint.
- **Palette and notice polish.** Recently used commands rank higher
  (typo'd input never pollutes history), running sessions show `· now` /
  `· active` badges, the status line tints muted/success/error, and
  repeated consecutive notices fold into `message (×N)`.
