# r105 2.4.0

r105 2.4.0 gives the harness its own window. `r105 window` opens a
native OS surface with a GPU-rendered terminal running a real shell;
`Ctrl+J` asks the model right there, answers stream into the `Ctrl+K`
panel, and tool calls run the same approve-then-execute loop as the TUI
with inline `y`/`a`/`n` verdicts. The release also adds a terminal
prototype, first-class reasoning traces, and anchored editing tools.

## Highlights

- **Native window.** `r105 window` opens r105 in its own OS window
  (winit, wgpu, glyphon over the system monospace font) hosting the
  same PTY shell core. Typing runs in the shell, resize reflows the
  grid, and `Cmd/Ctrl+Q` or the close button quits. `--smoke N`
  renders N frames and exits with a frame report for automated checks;
  `--smoke-chrome` seeds the composer, AI panel, and approval bar, and
  `--smoke-snapshot` captures the final frame as PPM.
- **AI in the window.** `Ctrl+J` opens the composer (`Enter` sends,
  `Alt+Enter` newline, `Esc` closes, `Ctrl+C` cancels a live run).
  Tokens stream into the AI panel (`Ctrl+K`, arrows select,
  `PgUp`/`PgDn` scroll the selected block). Tool calls reuse the TUI's
  approve-then-execute loop: `y` once, `a` always (per-file session
  grants for writes), `n` deny. Each window session checkpoints its
  history and restores with `--session <name> window`.
- **Window input.** Drag selects terminal text, `Cmd/Ctrl+C/V` copies
  and pastes (bracketed paste when the shell supports it), the wheel
  and scroll keys reach scrollback, and IME input commits into the
  focused surface.
- **Terminal prototype.** `r105 terminal` opens a persistent PTY shell
  with a block list (command, cwd, elapsed); `r105 terminal -- <cmd>`
  runs one command in a fresh PTY and reports the exact exit code.
  `harness` and `send` are untouched.
- **Reasoning traces.** Streamed reasoning renders as a collapsed
  preview separate from the reply; `/reasoning` now accepts
  `auto|off|none|disabled|low|medium|high|max|xhigh`; `/tokens` reports
  prefix-cache hits and the footer shows accumulated hits.
- **Anchored edits.** New `edit_file` (one anchored span) and
  `apply_patch` (structured Add/Update/Delete with @@ hunks) tools;
  approval cards preview writes and `a` grants per-file session skips.
- **Instructions and sandbox probe.** Every request carries the
  project instruction chain (global plus workspace AGENTS files), and
  a new `sandbox` subcommand probes the selected backend.
- **macOS app.** `packaging/build_macos_app.sh` bundles an ad-hoc
  signed `r105.app`; launching from the bundle opens the window
  surface.

## Fixed

- Window AI cancellation preserves the session and queued prompts.
- Window Once and Deny verdicts no longer create persistent approval
  grants.
- Interrupted window tool rounds retain complete call/result history
  for the next backend request.

## Upgrade

Drop-in replacement for 2.3.1: config, existing sessions, and the TUI
are unchanged; `terminal` and `window` are new surfaces alongside
`harness` and `send`. Window sessions live in the usual sessions
directory as `window-<uuid>`. Public distribution of the macOS bundle
still requires Developer ID signing and notarization; the script ships
an ad-hoc signed local build.
