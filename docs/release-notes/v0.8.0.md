## r105 0.8.0

This release adds live provider switching to the AI harness and makes direct
llama.cpp connections work with the standard `/v1` API base URL.

### Provider connections

- `/connect llamacpp` selects a local llama.cpp server at
  `http://127.0.0.1:8080/v1`
- `/connect ollama`, `/connect lmstudio`, `/connect vllm`, and `/connect router`
  cover common local and router deployments
- `/connect openai`, `/connect groq`, `/connect openrouter`, `/connect deepseek`,
  and `/connect together` provide cloud presets
- `/connect url <https://host/v1>` supports other OpenAI-compatible APIs
- `/provider` aliases `/connect`; `/connect status` reports the active mode and
  URL; provider changes apply immediately in the running TUI
- API keys remain environment variables and are never written to the config
  file

### TUI and client fixes

- The slash-command palette now scrolls the highlighted command into view as
  the list extends below the docked palette.
- Direct-client URL joining accepts both host roots and bases that already end
  in `/v1`, avoiding `/v1/v1` requests and probing llama.cpp `/props` at the
  server root.

### Compatibility

The release workflow publishes binaries for Linux x86_64, macOS x86_64 and
arm64, Windows x86_64 and arm64, and FreeBSD amd64. It also builds Ubuntu/
Debian, Arch, Fedora/RHEL, FreeBSD, and best-effort Alpine packages as
described in the README.
